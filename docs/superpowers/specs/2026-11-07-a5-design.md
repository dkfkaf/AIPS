# A5 — JSONL 로그·파이프라인 통합 설계안

상태: 2026-11-07 사용자 “A5 설계대로 진행해”로 승인. 현재 폴더에서 직접 구현·검증하며 자동 commit/push는 하지 않는다.

실행 결과: 2026-11-08 A5 완료. 최종 세 구성 각각225/225·실패/skip0·포맷 통과. 독립 리뷰 중요1건 수정/경미3건 보류. [A5 증거](../../a5-validation-2026-11-08.json)와 [한계](../../known-limitations.md)에 검증 범위와 API 세부 결정을 기록했다. A6/AI는 이번에 구현하지 않았다.

## 목적과 현재 기준

한 PCAP에서 파싱 → Flow → TCP 재조립 → 룰 판정 → JSONL을 재현한다. [PROJECT_SPEC.md](../../../PROJECT_SPEC.md) F-06과 [IMPLEMENTATION_PLAN.md](../../../IMPLEMENTATION_PLAN.md) A5가 기준이다. [A4 실행 증거](../../a4-validation-2026-11-07.json)의 최종184/184씩 세 구성 통과를 선행 기준으로 삼는다. 현재 A4 소스47개가 해당 증거와 같음을 확인했다.

현재 AIPS 폴더의 미커밋 A4 변경을 보존하고 직접 구현·검증·최종 독립 리뷰를 진행한다. 자동 commit/push는 하지 않는다. C++20·기존 nlohmann/json·단일 스레드를 유지한다. KMP·룰 우선순위·재전송 정책은 바꾸지 않는다. A6 live, A7 실제 NFQUEUE/Drop, AI는 구현하지 않는다. **IPS A0~A8 완성 → 사용자 자체 테스트 → AI 착수 지시 → B0**라는 사용자 결정을 유지한다.

## 접근 방법

1. **제안: Engine의 판정 계산과 EventLogger의 출력을 분리한다.** CLI의 기존 처리 순서를 재사용 가능한 Engine으로 옮긴다. Engine은 소유 메타데이터 결과만 반환하고 로거는 그 결과를 JSONL로 쓴다. 판정 계산 중 파일/콘솔 로그 I/O가 없으므로 로거 실패와 검사 결과를 별도로 검증할 수 있다.
2. **대안: CLI의 기존 print 함수에서 바로 JSON을 생성한다.** 변경은 작지만 Flow 종료 컨텍스트·오류·통계가 CLI에 계속 섞이고 후속 입력 어댑터가 같은 파이프라인을 사용하기 어렵다.

사용자는 첫 번째 방식의 설계를 승인했다. 비동기 로깅·스레드·무제한 이벤트 큐·로그 회전·외부 로그 서비스는 도입하지 않는다.

## CLI와 파일 정책

- `--log PATH`를 선택 옵션으로 추가한다. 옵션이 없으면 기존 A4 콘솔 출력과 오류 코드 계약을 유지한다. 파일 지정 시 기존 콘솔과 별개로 JSONL을 쓴다.
- `--log -`는 stdout을 JSONL 전용으로 사용한다. 이 모드에서는 기존 패킷/Flow/룰의 상세 콘솔 출력을 생략하고 stderr에 진단·종료 요약만 남긴다. stdout에 도움말·일반 텍스트를 섞지 않는다. PCAP stdin 입력 지원은 추가하지 않는다.
- 파일 로그는 **새 파일만 생성**한다. Linux `O_CREAT|O_EXCL|O_CLOEXEC`, 생성 권한0600을 요청하고 RAII로 닫는다. 기존 파일·심볼릭 링크·하드 링크 경로는 거부하며 append/덮어쓰기는 지원하지 않는다. 입력 PCAP/룰 파일과 같은 경로를 지정해도 원본을 수정하지 않는다. 상위 디렉터리를 자동 생성하지 않는다. 실제 접근 권한은 파일시스템/umask/ACL에 따르며 Linux 네이티브 파일시스템의0600 검사와 Windows 마운트의 ACL 보장을 동일하게 주장하지 않는다.
- 사용법·중복/누락 옵션은2, 설정/입력/로그 열기/처리/출력 실패는1, EOF 처리와 출력이 정상 완료되면0이다. EOF 코드0이 skipped/rejected/incomplete가 없다는 뜻은 아니다.
- 룰 파일·설정 검증을 먼저 하고 로거를 연 뒤 PCAP을 읽는다. 설정 검증/로거 초기화 자체가 실패하면 stderr로 보고하며 JSONL 파일이 존재한다고 보장하지 않는다. 로거가 준비된 뒤의 PCAP 열기·읽기/처리 오류는 가능한 경우 engine_error와 불완전 종료 stats로 기록한다.
- 오류가 난 새 로그 파일은 지우지 않는다. 부분 결과와 실패 증거를 보존한다. 정상 쓰기/flush/close 성공은 확인하지만 fsync 기반 전원 장애 내구성을 보장하지 않는다.

## 공통 JSONL 스키마 v1

한 물리적 줄에 JSON 객체 하나와 LF 하나를 쓴다. 모든 이벤트에 다음 키를 둔다.

| 필드 | 타입/의미 |
| --- | --- |
| schema_version | 정수1 |
| event_type | alert, verdict, flow, parse_error, reassembly_warning, stats, engine_error |
| event_id | 실행 내 증가하는 양의 정수, 발행 시도 순서 |
| packet_number | 관련 PCAP 레코드 번호, 종료/일반 오류는 null 가능 |
| timestamp | 알려진 캡처 시각의 UTC ISO8601 마이크로초 문자열, 표현 불가/미관측은 null |
| timestamp_us | 정확한 Unix microseconds 정수, 미관측은 null |
| flow_id | 고유 uint64 정수 또는 null |
| src_ip/dst_ip | 숫자 IPv4를 dotted 문자열로 변환, 알 수 없으면 null |
| src_port/dst_port | 정수 또는 null |
| protocol | tcp/udp 또는 null |
| mode/enforced | 이번 단계는 pcap / false 고정 |
| action | 이벤트에 맞는 alert/drop/pass/allow/skip/observe/error/none |
| sid | 관련 룰 SID 또는 null |
| message | 문자열. raw payload는 저장하지 않음 |

숫자 ID/카운터를 double로 바꾸지 않는다. 기존 F-06 예시는 의미를 설명한 것이며 이번 자체 스키마의 flow_id 타입은 정수로 확정한다. Suricata EVE 호환을 주장하지 않는다.

timestamp는 처리 벽시계가 아니라 캡처 시각이다. 패킷은 실제 captured_at, 만료·EOF·stats는 캡처 watermark를 사용하고 Flow의 first_seen/last_seen을 별도 기록한다. 역순 캡처의 event_id는 증가하지만 timestamp는 되돌아갈 수 있다. 빈 PCAP/첫 패킷 전 오류에는 가짜 시각을 만들지 않고 null을 사용한다. UTC 문자열 범위를 벗어난 유효 정수 시각은 timestamp=null과 timestamp_us 원값, timestamp_status=out_of_range로 남긴다.

JSON 직렬화는 ASCII escape를 사용하며 DEL도 `\u007f`로 바꾼다. LF/CR/ESC/C1/Unicode 줄·문단 구분자가 실제 로그 줄/제어문자로 나오지 않게 한다. 외부 예외 문자열의 잘못된 UTF-8은 replacement로 인코딩한다. 오류 message는 최대4096바이트로 제한하고 잘랐으면 message_truncated를 표시한다. 룰 message는 기존1024바이트 제한을 유지한다. 한 레코드 최대64 KiB이며 소스별 정해진 필드만 생성한다.

## 이벤트 의미

- **alert:** 중복 억제 후 발행하는 alert 또는 drop RuleMatch. action은 해당 룰의 alert/drop이고 sid/scope/match_end를 기록한다. pass는 경고로 세지 않고 verdict에 표시한다.
- **verdict:** 파싱된 지원 패킷마다1개. action=allow/drop, terminal sid와 matched_action=pass/drop, rule_matches_emitted/suppressed, rules_enabled를 구분한다. terminal이 없으면 sid=null이다. 룰이 없으면 Allow와 reason=no_rules다. packet 룰만 검사한 경우와 제한된 stream window의 존재를 구분한다. A4의 bool 의미를 정확히 전달하도록 JSONL 이름은 stream_window_available로 한다.
- **flow:** created/expired/eof/aborted 수명 이벤트. 방향별 카운터·IP 바이트·시작/마지막 시각·단순 TCP 상태와 종료 사유를 기록한다. 종료 이벤트의 source/destination은 최초 관측 방향이고 direction=null이다. 두 방향의 재조립 최종 요약에는 payload 없이 bytes/pending/FIN/불완전 이유만 둔다.
- **parse_error:** 파서의 안정된 reason, 캡처/원본 길이와 packet_number. 모르는 endpoint/Flow를 추측하지 않고 null로 둔다. action=skip이며 정상 Allow로 기록하지 않는다.
- **reassembly_warning:** A3의 midstream/gap/conflict/limit/invalid/reset 등 이력과 방향·바이트 수. gap_filled 알림은 같은 이벤트 계열에 severity=info/resolved=true로 구별한다. 경고는 security alert와 별개다. 현재 A3의 반복 reset 알림 한계는 유지하며 이것을 실제 RST 패킷 수로 해석하지 않는다.
- **engine_error:** Flow 용량 거부, 검출 상태 예산, PCAP/처리 오류 등 안정된 error_domain/reason을 기록한다. Flow 추적 거부 뒤에도 packet 룰 판정은 가능하므로 그 패킷의 verdict를 생략하지 않는다. logger 자체가 실패한 경우 같은 실패 sink에 오류 이벤트를 억지로 쓰지 않는다.
- **stats:** 종료/실패 요약. packets_total/parsed/skipped, flows_created/expired/active_at_finish/rejected, 재조립 바이트·충돌·불완전 방향, 아래 정의의 룰 카운터, simulated_drop_packets, actual_drop_packets=0, 로그 성공/실패/미기록 수를 구분한다. capture_complete는 EOF 도달 여부다. JSON에는 생성 시점의 log_status_at_emit/로그 카운터만 남기고, 이후 flush/close까지 성공했다는 log_complete=true는 기록하지 않는다. 전역 inspection_complete=true 같은 주장도 하지 않는다.

pass와 중복 억제된 terminal 룰도 매 패킷 verdict에는 sid/판정이 남는다. alert 이벤트 수와 시뮬레이션 Drop 패킷 수가 같다고 가정하지 않는다. 룰 카운터는 로그 쓰기 성공 여부와 독립적이다.

- rule_matches_emitted는 중복 억제 뒤 Engine이 반환한 RuleMatch 수로 pass를 포함한다. 실제 JSONL 쓰기에 실패해도 감소하지 않는다.
- rule_matches_suppressed는 중복 억제로 이벤트만 생략한 대표 match 수다. rule_matches_total은 emitted+suppressed다. 모두 실제 평가한 룰당 관측당 대표1건이며 전체 문자열 occurrence 수나 terminal 뒤 생략한 룰의 match 수가 아니다.
- detections는 emitted RuleMatch 중 action=alert/drop인 논리적 신규 탐지 수다. pass와 suppressed는 제외하며 logger 장애로 감소하지 않는다. 실제 기록한 alert 줄 수는 별도의 alert_events_written으로 센다.
- simulated_drop_packets는 현재 패킷 판정이 Drop인 횟수여서 억제된 재전송 Drop도 포함한다.

stats의 log_events_written은 stats 자신이 성공한 경우 그1건까지 포함하지만, 이는 sink가 수락한 레코드 수이지 저장 내구성 보증이 아니다. 로그 완료 여부의 최종 권위는 명시적인 logger finish(파일 flush/close 또는 빌린 스트림 flush) 이후의 종료 코드와 stderr/콘솔 요약이다. 그 요약만 log_complete를 확정한다. JSON stats를 쓴 뒤 최종 flush/close가 실패하면 종료 코드1·요약 실패로 보고하고, 이미 쓴 stats를 수정하거나 성공 완료로 간주하지 않는다.

## Engine과 수명

새 engine.hpp/src/engine.cpp가 Parser/FlowTable/Reassembler/선택 RuleEngine을 소유·조정한다. 정확한 C++ 값 타입 이름은 실행 계획에서 정한다.

- `inspect(PacketEnvelope)`는 입력을 동기 소비해 현재 패킷의 파싱 결과·Flow 관측·재조립 요약·룰 판정과 이번에 만료한 Flow 메타데이터를 소유 값으로 반환한다. capture bytes/payload/prefix span은 결과나 로거에 저장하지 않는다.
- inspect 안에서 로그 I/O를 수행하지 않는다. CLI는 결과를 얻은 다음 콘솔/JSONL로 발행한다. 향후 A7 adapter가 판정 전달 후 로그를 호출할 수 있는 경계이며, 실제 NFQUEUE verdict 의무가 이번에 검증됐다고 주장하지 않는다.
- 만료는 기존처럼 파싱 실패 패킷의 캡처 시각도 반영한다. 만료 callback에서 RuleEngine 상태를 제거하고 재조립 최종 요약을 복사한 뒤 배열을 해제한다. 종료 컨텍스트가 사라지기 전에 FlowSnapshot을 함께 보관한다.
- 이벤트 문자열 큐를 쌓지 않는다. 한 결과에 담기는 종료 Flow 기록 수는 해당 엔진의 활성 Flow 수(max_flows) 이하, RuleMatch 수는 활성 룰 수(최대1024) 이하다. 각 Flow 기록은 숫자/고정 상태뿐이다. CLI는 결과 하나를 발행·폐기한 뒤 다음 패킷을 읽으며 PCAP 전체를 메모리에 모으지 않는다. 이 상한은 전체 RSS 보장이 아니다.
- FlowTable에 읽기 전용 방문 API를 추가해 EOF의 활성 FlowSnapshot을 얻는다. 기존 observe/expire의 의미·반환값은 유지한다. 종료 기록을 flow_id 순으로 정렬해 unordered_map 순서에 로그가 좌우되지 않게 한다.
- `finish(reason)`은 EOF/abort 최종 기록과 stats를 만든다. EOF에 TCP 배열/룰 watermark를 정리하고 Flow metadata는 마지막 통계와 종료 기록을 위해 엔진 소멸까지 보관할 수 있다. 기존 콘솔 flow_summary active는 마지막 캡처 시각의 값이다.
- finish 반복 호출은 종료 이벤트를 중복 생성하지 않는다. finish 뒤 inspect는 명확히 거부하고, 다음 PCAP에는 새 엔진을 사용한다. 구성/처리/할당 오류는 정상 Allow로 바꾸지 않는다. 치명적 메모리 부족에서 최종 로그/통계까지 반드시 할당·출력할 수 있다고 보장하지 않는다.

## 로거 실패 정책

EventLogger는 파일 또는 빌려 받은 ostream에 동기 기록한다. 직렬화와 쓰기/flush 예외를 로거 상태로 변환하며 이미 계산한 DetectionDecision을 바꾸지 않는다. 소유 FD는 RAII로 닫고 부분 쓰기/EINTR/0바이트 쓰기를 처리한다. 무한 재시도나 비동기 큐를 만들지 않는다.

로거의 명시적인 finish는 flush와 소유 FD close 결과를 관측하고 멱등적으로 완료 상태를 반환한다. 소멸자는 남은 자원의 비예외 정리만 맡는다. 소멸자에만 의존해 close 오류를 놓치거나 종료 코드를 먼저 확정하지 않는다. 빌린 stdout/ostream은 flush하되 소유권을 빼앗아 닫지 않는다.

최초 직렬화/크기/쓰기/flush 실패 뒤에는 해당 sink를 failed로 고정한다. failed 기록과 이후 미기록 이벤트를 카운터로 세고 같은 sink에 추가 레코드를 붙이지 않는다. 부분 쓰기라면 마지막 줄이 불완전할 수 있으므로 성공 코드나 완전한 JSONL이라고 보고하지 않는다. stderr에는 가능한 경우 한 번의 진단과 종료 요약을 남긴다.

PCAP 모드에서는 로그 실패 뒤에도 나머지 입력의 판정 계산과 정상적인 상태 정리를 계속하고 마지막에 코드1을 반환한다. 따라서 configured-budget/로그 실패를 정상 전체 성공으로 숨기지 않는다. 입력/엔진 자체의 치명적 오류나 기존 human 콘솔 장애는 기존 오류 정책대로 중단할 수 있다. stdout JSONL 모드는 human 상세 출력을 생략하므로 stdout 장애를 로거 실패로 관리한다. 단위 테스트에서 sink가 실패해도 뒤 패킷의 Drop/Pass 계산과 카운터가 유지되는지 확인한다.

이 설계는 로그의 성공과 판정의 독립성을 제공하지만 blocking I/O의 시간 상한이나 실제 Inline 지연을 보장하지 않는다. A7에서 verdict-before-publication 순서와 격리 테스트를 별도로 검증해야 한다.

## 파일 변경과 검증

새 include/miniips/event.hpp, event_logger.hpp, engine.hpp와 src/event_logger.cpp, src/engine.cpp를 중심으로 구현한다. 이벤트 직렬화 함수의 분리 파일은 구현자가 필요에 따라 정한다. CLI는 옵션·sink 생성·기존 human rendering·종료 코드를 맡고 중복 파이프라인은 남기지 않는다. CMake/테스트/fixture와 README·설계 결정·한계·테스트 계획·A5 실행 증거를 갱신한다.

## 설계 검토 기록

2026-11-07 독립적인 구현 관점 검토가 최종 stats/flush 시점과 룰 카운터 집계식 두 가지를 확인 요청했다. 작성자 선택으로 JSON stats는 생성 시점 상태만 표현하고 최종 성공은 logger finish 뒤 종료 코드/요약에서 확정하도록 했다. 또한 논리적 emitted/suppressed/detections와 실제 로그 쓰기 수를 분리하는 집계식을 명시했다. 사용자만 결정할 미정 사항은 없으며 제품 코드·테스트 실행이나 설계 승인을 뜻하지 않는다.
