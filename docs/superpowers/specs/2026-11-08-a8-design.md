# A8 — 종합 검증·문서화

상태: 2026-11-09 A8/A단계 개발자 검증 완료. 세 구성262/262·실제 격리14+11+4각각·성능12회·독립 리뷰 신규 결함0건을 [실행 증거](../../a8-validation-2026-11-09.json)에 기록했다. 기준 HEAD f912811bf0e21d0fb81e799d511febf12c840972(A7), 시작 작업 트리 clean. A8 요청은 직전 설명한 종합 검증·성능 기준·재현 가이드 작업의 실행 지시다. 이미 정한 접근을 다시 승인받지 않는다.

## 목표와 접근

F-01~F-06의 실제 완료 증거를 연결하고 C++ 엔진 단독 기준 성능을 저장한다. 권장 경로는 기존 단위/PCAP/live/NFQUEUE 검사 재사용 + 부족한 시험만 추가하는 것이다. 검증용 별도 엔진/대규모 리팩터링은 실제 CLI를 검증하지 못하고, 기존 UDP 시험만 재실행하면 TCP/성능 공백이 남으므로 채택하지 않는다. 개별 측정 기본값은 작성자 선택이다.

현재 폴더에서 진행하고 자동 commit/push를 하지 않는다. A0~A7 증거 JSON/ignored 로그를 덮어쓰지 않는다. A8 이후 사용자 자체 IPS 테스트·결과 확인·명시적 AI 착수 지시 전에는 B/C를 시작하지 않는다.

## 검증 범위

1. 기존257 CTest와 포맷, Debug/Release strict clang-tidy/ASan+UBSan 재실행. 고정 시드 혼합 정상/손상 Ethernet/L3 입력의 Engine 검사와 bounded 메모리·종료 정리 검사1개를 추가한다. 무작위 검사는 보안 완전성 증명이 아니다.
2. 기존 실제 격리 NFQUEUE14와 live11 시나리오를 각 구성에 유지한다. 새 TCP 검증기는 기존 최적화 Python/namespace 선검사를 재사용하는 안전 회귀1개를 갖는다(일반 CTest 예상262: robustness1/guard1/overflow 오류 주입3 추가). 실제 네트워크 명령보다 먼저 검사한다.
3. 새 격리 TCP 시험: 정상/packet Pass/Alert 전달, packet Drop 미도착, HEL 전달 후 LO로 HELLO stream Drop(이전 HEL은 소급 차단되지 않음). TCP ACK/재전송 때문에 고정 패킷 수를 가정하지 않는다. 유효 ID=attempts=accepted+dropped+failed, 성공 시 failed0; receipt ID 중복 금지. close 중 fallback의 개별 receipt 공백은 A7 정책을 유지한다.
4. 별도 UDP 큐의 reader를 SIGSTOP한 뒤 제한된16384 datagram을 보내 수신 소켓 압박을 만든다. SIGCONT 후 수신 오류의 오류 종료/통계·watchdog·정리를 확인한다. /proc/net/netfilter/nfnetlink_queue 원문을 저장하되 커널별 열 의미를 추정해 수치를 해석하지 않는다. lossless 처리나 모든 overflow syscall 경로를 보장하지 않는다.
5. 성능은 Release CLI의 PCAP→Engine→JSONL stdout(/dev/null) 전체 경로다. 합성 IPv4 UDP50000개/양방향128 Flow, no_rules와 fixed_rules를 각각 warm-up1+측정5회 실행한다. /usr/bin/time의 child CPU/RSS와 monotonic wall time을 저장한다. pps, wall/N의 평균 환산 비용, 개별 run 최대 RSS를 보고하며 wire throughput·패킷별 p99 지연·혼합 공격 탐지율로 일반화하지 않는다. 입력 생성은 시간 밖, 프로세스 시작/파싱/로그 직렬화/출력은 시간 안이다. 측정 전 CLI 처리/룰/로그 완료 카운터를 검사한다. 보고서는 새 파일만 생성한다.
6. rules/a8-baseline.json은 합성 검증 룰을 고정한다. C4에서 사용할 때 이 파일/해시와 적용 조건을 보존하며 실제 보안 탐지 범위를 과장하지 않는다. 평가 결과를 보고 몰래 룰을 변경하지 않는다.

## 안전·한계

네트워크 시험은 fresh anonymous netns만 사용하며 전용 table/loopback만 만든다. 호스트 인터페이스/방화벽·서비스 설치는 변경하지 않는다. nft 추출 도구는 A7의 로컬 도구를 재사용하고 해시를 기록한다. 압박 시험은 제한된 합성 트래픽이며 OOM/커널 crash/모든 손실 원인을 다루지 않는다. 기존 A5~A7 경미 사항은 검증 결과와 함께 정직하게 유지한다.
