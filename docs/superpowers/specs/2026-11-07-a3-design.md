# A3 — 방향별 TCP 재조립 설계안

상태: 2026-11-07 사용자 “진행해”로 설계와 구현·검증 승인 후 구현·인수 검증 완료. [실행 계획](../plans/2026-11-07-a3.md)과 [실행 증거](../../a3-validation-2026-11-07.json)를 참고한다. 중요한 리뷰 항목은 수정했고 경미 항목 2개는 명시적으로 보류했다.

## 목적과 범위

기존 A2의 `FlowObservation`과 A1의 `ParsedPacket`을 연결해 TCP의 방향별 연속 바이트를 제공한다. `HEL`과 `LO`는 `HELLO`가 되고, 순서가 바뀐 세그먼트는 누락이 채워진 뒤에만 연속 데이터로 노출한다. 근거는 [PROJECT_SPEC.md](../../../PROJECT_SPEC.md)의 F-02·F-03과 [IMPLEMENTATION_PLAN.md](../../../IMPLEMENTATION_PLAN.md)의 A3다. A2 기준선은 [검증 기록](../../a2-validation-2026-11-06.json)과 [재확인 기록](../../a2-resume-check-2026-11-07.json)이다.

C++20·단일 처리 스레드·오프라인 Ethernet/IPv4 PCAP·기존 의존성을 유지한다. 현재 AIPS 폴더의 미커밋 A0~A2 작업을 보존하고 같은 폴더에서 직접 구현하는 기존 작업 방식을 따른다. 자동 커밋과 push는 하지 않는다. 룰 엔진(A4), JSONL(A5), live/Inline, 실제 차단, AI는 구현하지 않는다.

## 접근 방법

1. **제안: 방향별 고정 깊이의 prefix + 존재 비트맵.** 최초 기준점 이후의 첫 N바이트만 보관한다. 도착한 위치에만 존재 표시를 하고, 구멍 없는 앞부분만 노출한다. 이미 노출한 바이트도 깊이 한도 안에서는 유지하므로 과거 재전송과 겹침 충돌을 비교할 수 있다. 깊이를 넘는 스트림은 불완전으로 표시한다. 메모리와 동작을 검증하기 쉬운 대신, 긴 스트림 전체를 검사하거나 메모리를 작은 단위로 늘리지 않는다.
2. **대안: 가변 세그먼트 목록 + 이동 창.** 작은 전송은 적은 메모리를 쓰고 긴 스트림을 계속 처리하기 좋다. 그러나 세그먼트 분할·병합, 메타데이터 상한, 버려진 과거 바이트의 충돌 검출 범위를 추가로 정해야 한다. 이번 교육용 A3에는 복잡도가 더 크다.

첫 번째를 작성자의 제안으로 제시했고 사용자가 설계대로 구현·검증을 진행하도록 승인했다. 두 방식 모두 first-seen이라는 명세 계약은 유지한다.

## 방향, 기준점과 순서

- 상태 키는 A2가 배정한 `flow_id`와 `FlowDirection`이다. fwd/bwd는 각각 독립된 시퀀스 공간과 버퍼를 사용한다. UDP에는 재조립 상태를 만들지 않는다.
- SYN을 관측하면 데이터 기준점은 `SEQ + 1`이다. SYN 자체는 출력 바이트가 아니다. SYN에 payload가 있으면 이 기준점부터 처리한다.
- SYN 없이 payload를 처음 관측하면 그 payload의 SEQ를 기준점으로 삼고 `midstream`을 계속 표시한다. 앞서 보지 못한 데이터를 추측하거나 나중에 과거 데이터가 왔다고 이미 노출한 prefix를 앞쪽으로 다시 쓰지 않는다. SYN 없는 순수 ACK는 데이터 기준점을 만들지 않는다.
- SYN과 payload보다 먼저 순수 FIN을 관측하면 FIN의 SEQ를 빈 데이터 기준점으로 정하고 `midstream`과 위치 0의 종료 표식을 남긴다. 뒤늦은 과거 데이터를 붙여 기준점을 바꾸지 않는다. 처음 관측한 종료만으로 이전 데이터가 없었다고 주장하지 않는다.
- 기준점보다 앞선 데이터는 재배치하지 않는다. 한 세그먼트가 기준점을 가로지르면 이전 부분을 제외하고 범위 안 부분만 처리한다. 미관측 앞부분은 불완전 이유로 남긴다.
- 비교 함수는 32비트 unsigned 차이를 이용한다. 동일·앞·뒤·정확히 반 바퀴 차이의 모호함을 구분하며 부호 있는 정수로 범위 밖 변환하지 않는다. 지원 깊이는 `1..2^31-1`이고 정확히 `2^31` 떨어진 SEQ는 `sequence_ambiguous`로 거부한다. 기준점에 상대적인 위치만 처리해 한 번 이상의 시퀀스 전체 회전을 복원했다고 주장하지 않는다.
- payload 범위와 FIN 위치의 계산은 충분히 넓은 정수로 먼저 검사한다. 숫자 넘침이나 잘못된 플래그 조합을 정상 데이터로 처리하지 않는다.

## 데이터 보관과 first-seen

- 콜백에서 받은 `span`을 저장하지 않는다. 허용된 payload 바이트를 재조립기가 소유하는 배열로 복사한다.
- 빈 위치에는 처음 받은 바이트를 저장한다. 이미 있는 위치의 같은 바이트는 중복이며 다시 추가하지 않는다. 값이 다르면 기존 값을 유지하고 해당 관측에 `overlap_conflict`를 한 번 기록한다. 비교 범위에는 대기 중인 데이터와 이미 노출한 prefix가 모두 포함된다.
- `contiguous_prefix`는 기준점부터 첫 구멍 직전까지다. 새 관측으로 늘어난 부분을 `newly_contiguous`로 함께 반환한다. 역순 데이터만 도착한 상태에서 구멍을 가로질러 검사할 수 없다.
- 갭은 현재 prefix 뒤에 보관된 데이터 또는 먼저 도착한 FIN으로 판정한다. 현재의 `gap_pending`과 최종 종료 때 남은 `gap`을 구분한다. 누락 데이터가 도착해 갭이 채워지면 연속 데이터가 늘어나지만 `midstream`·충돌·한도 초과 같은 이력은 지우지 않는다.
- 반환된 바이트 뷰는 다음 재조립기 변경 작업 전까지만 유효하다. 호출자는 그 안에서 검사하거나 필요한 데이터를 별도로 복사한다. 결과를 모아두는 무제한 출력 큐는 만들지 않는다.

## 메모리와 검사 깊이

- 기본 방향별 검사 깊이 N은 **65,536바이트**다. 이 설정이 보관 가능한 시퀀스 범위와 payload 배열 크기의 상한을 함께 결정한다. 별도의 무제한 스트림 이력을 두지 않는다.
- payload가 처음 허용될 때 해당 방향의 N바이트 배열과 `ceil(N/8)`바이트 존재 비트맵을 지연 할당한다. SYN/ACK만으로 payload 버퍼를 할당하지 않는다. 배열 크기는 이후 늘어나지 않는다.
- 기본 전체 재조립 예산은 **134,217,728바이트**다. 이 예산에는 두 방향의 실제 소유 payload 배열과 비트맵 크기를 모두 합산한다. N=65,536이면 방향당 73,728바이트를 사용한다. 예산을 넘길 할당은 수행하지 않는다.
- 방향 상태와 map 같은 고정 메타데이터는 A2와 동일한 최대 Flow 개수로 제한한다. 전체 예산은 재조립 배열에 대한 상한이며 할당자·컨테이너·libpcap·프로세스 전체 RSS의 정확한 상한은 아니다. 이 구분을 CLI 설명과 한계 문서에도 남긴다.
- 예산 부족으로 방향 버퍼를 만들 수 없으면 `memory_limit`을 표시하고 그 방향은 해당 Flow가 끝날 때까지 재조립하지 않는다. 바이트를 조용히 버렸다가 뒤에서 정상 스트림으로 재시작하지 않는다. 다른 방향과 다른 Flow의 기존 버퍼는 유지한다. 실제 할당 실패는 기존 런타임 오류 경로로 파일 분석을 종료한다.
- 범위 밖 데이터는 `depth_limit`으로 표시하고 범위 안 부분만 처리한다. 나중에 빈 위치가 채워져도 깊이 밖을 검사한 것으로 보고하지 않는다. 최대 개수 초과도 명확한 추적 거부로 표시한다.
- CLI에 `--tcp-stream-bytes N`, `--tcp-memory-bytes N`을 추가한다. 모두 양수·완전한 정수여야 하며 누락·중복·음수·범위 초과는 기존과 같은 사용법 오류 코드 2다. 작은 전체 예산은 유효한 설정이며 실행 중 명시적인 메모리 한도 이벤트로 관측한다.

## 종료, 이상 세그먼트와 정리

- FIN은 payload 바로 다음 시퀀스 위치의 종료 표식이다. 출력 바이트가 아니며 FIN 자체는 시퀀스 번호 1개를 소비한다. 먼저 받은 FIN만으로 앞의 갭을 채우거나 방향을 완전하다고 표시하지 않는다. FIN 이전 재전송과 누락 보충은 허용한다.
- 같은 FIN 위치의 재전송은 중복으로 처리한다. 다른 종료 위치나 FIN 뒤의 데이터는 이상 이벤트를 남기며 이미 받은 바이트와 종료 위치를 덮어쓰지 않는다. FIN을 수신한 방향만 종료 대상으로 삼는다. 충돌 비교를 위해 보관된 prefix는 Flow 만료 또는 파일 종료까지 유지한다.
- 새 FIN 위치보다 뒤에 이미 보관하거나 노출한 데이터가 있으면 그 FIN 세그먼트 전체를 `invalid_segment`로 거부한다. 기존 데이터를 소급 잘라내지 않고 종료 표식도 만들지 않는다. 반대로 FIN을 먼저 관측했다면 그 경계 이후에 나중에 온 데이터는 제외하고 이상으로 표시한다. 종료 경계에도 먼저 관측한 정보를 우선하는 이 단순 정책을 적용한다.
- RST는 두 방향을 불완전한 reset 종료로 표시하고 배열을 해제한다. 같은 Flow ID가 뒤의 패킷으로 조용히 재시작하지 않도록 제한된 종료 상태는 Flow 만료까지 유지한다.
- 같은 방향의 동일 SYN 재전송은 초기화하지 않는다. 이미 정한 기준점과 다른 SYN은 `session_reuse`로 표시하고 해당 방향의 추가 재조립을 중단한다. A2의 같은 tuple 재사용 시 통계가 합쳐질 수 있는 한계를 없앤 것으로 주장하지 않는다.
- SYN+FIN 또는 SYN+RST 같은 지원하지 않는 조합은 제어 처리보다 먼저 검사한다. `invalid_segment`를 남기되 그 세그먼트의 기준점 설정·payload 보관·FIN 처리·RST 종료/해제는 모두 수행하지 않는다. 완전한 TCP 수신 상태 머신이나 ACK/window 검증, OS별 정규화는 구현하지 않는다.
- A2 `FlowTable`의 `observe`와 `expire`에 선택적인 만료 알림 콜백을 추가한다. 기존 호출 형태와 반환값은 유지한다. 유효성 검사 후 기존 만료 절차에서 삭제 직전 ID를 알려 재조립 상태를 즉시 최종화·해제한다. 만료 ID를 무한히 쌓는 목록은 만들지 않는다. 콜백 실패는 기존 런타임 오류 경로로 중단하고 RAII로 정리한다.
- 파싱 실패 패킷도 현재처럼 캡처 시계의 만료를 진행한다. 어느 Flow인지 안전하게 알 수 없는 잘린 패킷을 임의의 스트림에 넣지 않고 기존 `parse_error`와 전체 skipped 수로 남긴다.
- EOF에서는 활성 재조립 상태를 모두 최종화하고 배열을 해제한다. FIN이 없는 방향은 `capture_end`, 남은 구멍은 `gap`, SYN 없이 시작한 방향은 `midstream` 등 이유를 보존한다. 유휴 만료는 `idle_timeout`으로 구별한다.
- 출력의 `contiguous`는 관측 범위의 연속성을 뜻한다. 전체 세션·완전한 TCP 정규화·완전한 보안 검사의 성공을 뜻하는 `complete=true`를 출력하지 않는다.

## 모듈과 인터페이스

새 `include/miniips/tcp_reassembler.hpp`, `src/tcp_reassembler.cpp`에 설정·상태·비교 함수·재조립기를 둔다. 필요하면 값 타입을 별도 `tcp_reassembly.hpp`로 분리하는 파일 배치는 구현자가 정한다.

제안 API의 역할:

```cpp
SequenceOrder compare_tcp_sequence(std::uint32_t lhs, std::uint32_t rhs) noexcept;

class TcpReassembler {
 public:
    explicit TcpReassembler(TcpReassemblyConfig config = {});
    ReassemblyUpdate observe(const FlowObservation& flow, const ParsedPacket& packet);
    void finish_flow(std::uint64_t flow_id, ReassemblyEnd reason,
                     const ReassemblyEventSink& sink);
    void finish_all(ReassemblyEnd reason, const ReassemblyEventSink& sink);
    TcpReassemblyStats stats() const noexcept;
};
```

`ReassemblyUpdate`에는 방향별 prefix/newly-contiguous 뷰, pending 수, 불완전 이유와 이번 관측의 이벤트를 둔다. 이벤트는 정해진 소수의 enum/비트 집합으로 제한하고 바이트마다 동적 객체를 만들지 않는다. 종료 콜백은 상태가 사라지기 전에 동기적으로 이벤트를 소비하며 예외·뷰 수명 계약을 헤더에 명시한다. 직접 API의 잘못된 ID·프로토콜·방향·TCP 메타데이터는 상태 변경 전에 거부한다.

CLI는 기존 패킷/Flow 출력에 재조립 바이트 수와 상태를 추가하고, 별도의 제한된 콘솔 이벤트와 `reassembly_summary`를 출력한다. payload 원문은 기본 출력하지 않는다. Flow 용량 거부 패킷은 재조립하지 않고 untracked로 표시한다. UDP 출력과 기존 오류 코드 계약은 유지한다. EOF 성공 코드 0이 gap·skipped·메모리 거부가 없다는 뜻은 아니다. A5 JSONL 형식은 미리 구현하지 않는다.

`CMakeLists.txt`, `tests/CMakeLists.txt`에 새 라이브러리·테스트·포맷 대상을 연결한다. CLI 통합, fixture 도구, README, `docs/design-decisions.md`, `docs/known-limitations.md`, `docs/test-plan.md`와 A3 실행 증거를 갱신한다. 관련 없는 기존 파일은 수정하지 않는다.

## 검증 계획과 완료 조건

1. 방향별 SYN 기준점에서 `HEL` + `LO`가 정확히 `HELLO`인지 확인한다. 처음부터 순서가 뒤바뀐 경우 SYN → `LO` → `HEL`로도 확인한다. SYN 없는 역순 첫 수집은 완전 복원 대신 명시한 midstream 정책을 검증한다.
2. 정·역방향 기준점과 데이터가 섞이지 않는지, UDP와 추적 거부 Flow에는 버퍼를 만들지 않는지 확인한다.
3. 동일 재전송, 완전/부분 중복, 대기 구간·이미 노출한 구간의 서로 다른 overlap, 중복이 신규 바이트에 섞인 경우를 독립적인 기대 바이트로 확인한다.
4. 여러 구멍, 일부 보충, 전체 보충, 영구 갭, FIN의 역순 도착, 방향별 FIN, RST, SYN 재전송/재사용과 미지원 flag 조합을 확인한다.
5. `0xffffffff → 0` 경계, 경계 양쪽의 재전송/갭, 동일 SEQ, 정확히 반 바퀴 차이를 검증한다.
6. 작은 깊이와 예산으로 정확한 한도 직전/경계/초과, 비트맵 반올림, 양방향·여러 Flow의 예산 공유, 거부 후 상태, 만료·RST·EOF 해제와 새 Flow의 공간 재사용을 확인한다. 입력 소유 버퍼를 바꾼 뒤에도 저장한 데이터가 유지되는지도 확인한다.
7. Flow 자동 만료·파싱 오류 중 만료·동일 tuple 새 ID·역순 캡처 시계에서 오래된 재조립 상태가 남거나 다른 Flow에 붙지 않는지 확인한다.
8. 합성 PCAP으로 CLI의 순서 복원 건수·충돌·gap·midstream·상한·정리와 옵션 오류, 출력 실패를 확인한다. 실제 네트워크나 방화벽은 변경하지 않는다.
9. 새 테스트의 실패를 먼저 확인하고 최소 구현한다. 기존 101개 회귀 검사를 보존해 Debug, Release/clang-tidy, ASan/UBSan과 포맷 검사를 실제 실행한다. 테스트 개수·실패/skip·수동 명령·환경·증거를 구분해 기록하고 최종 코드 리뷰를 받는다.

위 인수 기준을 실제로 검증한 뒤에만 A3 완료로 보고한다. 이전 패킷을 소급 차단할 수 없으며 향후 stream 룰은 뒤에서 관측한 패킷에만 영향을 줄 수 있다는 제한도 문서에 유지한다. A4는 별도 사용자 지시 후에 진행한다.

## 설계 검토 기록

2026-11-07 독립적인 구현 관점 검토에서 나온 세 가지 경계 조건을 문서에 반영했다. 기존 데이터보다 앞선 FIN은 거부하고, 잘못된 SYN 조합의 제어 효과도 무시하며, 먼저 받은 순수 FIN은 midstream 빈 기준점으로 기록한다. 모두 기존 명세 안에서 작성자가 정한 구현 정책이다. 제품 코드·테스트 실행·A3 완료를 의미하지 않는다.
