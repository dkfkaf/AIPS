# A3 TCP Reassembly Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** 방향별 TCP prefix를 복원하고 재전송·겹침·누락과 자원 한계를 명시한다.

**Architecture:** 승인된 고정 깊이 배열과 존재 비트맵을 사용한다. FlowTable의 동기 만료 알림으로 재조립 상태를 제거하고 PCAP CLI에서 결과를 소비한다.

**Tech Stack:** C++20, CMake/Ninja, GoogleTest, Ubuntu 24.04 WSL2, 기존 시스템 패키지.

**Spec:** [승인된 설계](../specs/2026-11-07-a3-design.md). 2026-11-07 사용자가 “진행해”로 설계에 따른 구현과 검증을 승인했다.

## Global Constraints

- 방향별 깊이 65,536바이트, 전체 배열 예산 134,217,728바이트, Flow 수 10,000개 기본값. payload+존재 비트맵을 예산에 합산한다.
- first-seen, 방향 분리, wrap-aware 비교, borrowed 입력을 소유 배열로 복사한다.
- 기존 A0~A2 미커밋 변경을 보존하며 현재 폴더에서 직접 실행한다. 자동 commit/push 없음.
- A3만 구현한다. 룰·JSONL·live·Inline·AI·호스트 방화벽 변경 없음.
- 기존 설계 승인과 직접 구현 요청에 따라 아래 계획을 실행한다. 기술적 세부 사항은 ledger에 기록하고 중간 재승인을 요구하지 않는다.

## Review Focus

- 이미 노출/보관한 바이트보다 앞선 FIN: 새 종료 세그먼트를 거부하고 기존 prefix를 유지한다(Task 1).
- SYN+RST 우선순위: 잘못된 세그먼트는 reset 부작용도 없다(Task 1).
- 정확히 반 시퀀스 공간 차이: 임의의 앞/뒤 해석 없이 모호함을 표시한다(Task 1).
- 파싱 실패·역순 시각 중 만료: Flow와 재조립 상태가 함께 해제된다(Task 2/3).
- 종료 이벤트 출력 실패: 성공 코드로 누락을 숨기지 않고 RAII로 정리한다(Task 2/3).

## Task 1: 재조립 코어

**Files:** 새 `include/miniips/tcp_reassembler.hpp`, `src/tcp_reassembler.cpp`, `tests/test_tcp_reassembler.cpp`; 수정 CMake 두 파일.

**Interfaces:** `compare_tcp_sequence(uint32_t,uint32_t) noexcept -> SequenceOrder`; `TcpReassembler(TcpReassemblyConfig)`; `observe(const FlowObservation&, const ParsedPacket&) -> ReassemblyUpdate`; `finish_flow(uint64_t,ReassemblyEnd,const ReassemblyEventSink&)`; `finish_all(ReassemblyEnd,const ReassemblyEventSink&)`; `stats() const noexcept -> TcpReassemblyStats`. Update는 prefix/newly_contiguous span, pending 수, issues/events, FIN 상태를 제공한다. 이벤트 sink는 Update를 동기 소비한다.

- [x] RED: SYN 99, `HEL` at100, `LO` at103 → prefix `HELLO`; SYN → `LO` → `HEL`도 같은 결과. 중복은 새 바이트 0이다.
- [x] RED: 방향 분리·midstream·입력 수명·완전/부분 overlap·여러 갭·wrap/half-range·FIN/RST/잘못된 SYN·한도 직전/경계/초과·비트맵 반올림·공유 예산·정리/재사용·잘못된 API 입력을 테스트한다. 기능 미존재로 새 테스트 빌드 실패를 확인한다.
- [x] GREEN: 상기 인터페이스와 bounded prefix 구현. 유효성 검사는 상태 변경 전, 종료 콜백은 동기 처리한다. CMake에 라이브러리/테스트/포맷 대상을 등록한다.
- [x] 검증: `cmake --build build && ctest --test-dir build -R 'TcpSequence|TcpReassembler' --output-on-failure` → 전부 통과. 로그 저장, 자동 커밋 생략.

## Task 2: Flow 수명 연결

**Files:** 수정 `include/miniips/flow_table.hpp`, `src/flow_table.cpp`; 새 `tests/test_reassembly_lifecycle.cpp`.

**Interfaces:** `FlowExpirySink = std::function<void(const FlowSnapshot&)>`; `observe(const ParsedPacket&, const FlowExpirySink& = {})`; `expire(microseconds,const FlowExpirySink& = {})`. 기존 반환/인수 사용은 유지한다. Task 1의 `finish_flow`를 만료 콜백에서 호출한다.

- [x] RED: observe의 자동 만료 때 실제 재조립 메모리가 0이 되고 새 ID는 예전 데이터 없이 시작한다. 명시 만료·역순 시계·거부 전 만료·콜백 예외도 확인한다. 새 overload 부재의 빌드 실패를 확인한다.
- [x] GREEN: 삭제 직전 콜백, 삭제 후 즉시 만료 집계. 콜백이 던지면 해당 Flow는 지우지 않고 파일 처리를 중단한다. 이미 지운 Flow 집계는 일관성을 유지한다.
- [x] 검증: 관련 lifecycle + 기존 Flow 테스트 전부 통과. 로그 저장, 자동 커밋 생략.

## Task 3: PCAP CLI 연결

**Files:** 수정 `src/cli.cpp`, CMake 포맷/테스트 대상; 새 `tests/test_cli_reassembly.cpp`, `tests/fixtures/reassembly_fixtures.hpp`. 필요 시 기존 fixture 도구에 PCAP 시나리오 추가.

**Interfaces:** 새 옵션 `--tcp-stream-bytes N`, `--tcp-memory-bytes N`; 패킷 뒤 `stream_bytes`, `stream_new_bytes`, `stream_pending_bytes`와 상태; 동기 `reassembly_event`/`reassembly_end` 및 EOF `reassembly_summary` 콘솔 출력. 기존 CLI/Flow 출력 부분 문자열과 오류 코드 유지.

- [x] RED: PCAP SYN→LO→HEL→FIN에서 신규 바이트 0/0/5/0, 충돌·gap·midstream·메모리/깊이 제한·UDP/거부·파싱 실패 중 만료·EOF 해제·설정 오류·출력 실패를 독립 기대값으로 확인한다. 기존 CLI에서 실제 assertion 실패를 확인한다.
- [x] GREEN: A1→A2→A3 연결, 콜백 만료/EOF 정리, 제한된 메타데이터 출력. payload 원문은 출력하지 않는다.
- [x] 검증: 새 CLI 검사와 전체 Debug 회귀 검사 통과. 실제 프로세스 PCAP·비특권 계정 실행도 확인한다.

**Files:** `README.md`, `docs/design-decisions.md`, `docs/known-limitations.md`, `docs/test-plan.md`, A3 실행 증거 JSON, 승인 설계/이 계획의 상태.

- [x] `cmake --build build --target format-check` → 성공.
- [x] Debug 전체 CTest, Release/clang-tidy 빌드+전체 CTest, ASan/UBSan 빌드+전체 CTest → 실패/skip 0. 각 로그/XML 저장.
- [x] actual commands/환경/결과/소스 해시와 한계를 기록한다. RSS·성능·전체 TCP 세션 검사를 보장하지 않는다.
- [x] 승인 기준선 대비 A3만 포함한 리뷰 패키지를 만들고 fresh-context 최종 리뷰 1회. 중요 문제는 한 번의 수정 과정에서 RED→GREEN 및 관련 전체 검증으로 해결한다.

자체 검토: 설계의 각 요구는 Task 1~3과 해당 테스트에 연결되어 있고 Task 4가 실제 증거를 남긴다. 구현 scratch는 이미 ignored인 `build-a3-work/`를 사용한다. 기존 미커밋 작업 때문에 HEAD만으로 A3 diff를 구분하지 않고 수정 전 파일을 이 경로에 복사한다.
