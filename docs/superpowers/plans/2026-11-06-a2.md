# A2 양방향 Flow 추적 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. 사용자가 현재 AIPS 폴더의 직접 구현을 승인했다. 구현 중 추가 승인을 반복 요청하지 않는다.

**Goal:** PCAP의 요청·응답을 같은 Flow로 추적하고 방향별 통계, 유휴 만료와 개수 제한을 검증한다.

**Architecture:** endpoint를 정렬한 FlowKey와 unordered_map을 사용한다. 통계의 fwd는 처음 관측한 방향이며, 만료는 단조 캡처 시계와 테이블 순회로 처리한다. payload를 보관하지 않는 고정 상태의 스냅샷을 값으로 반환한다.

**Tech Stack:** C++20, 기존 CMake/Ninja·GoogleTest/CTest·libpcap, clang 도구 18, ASan/UBSan.

**Spec:** [승인 설계](../specs/2026-11-05-a2-design.md), [PROJECT_SPEC.md](../../../PROJECT_SPEC.md) F-02·8.1, [IMPLEMENTATION_PLAN.md](../../../IMPLEMENTATION_PLAN.md) A2.

## Global Constraints

- 현재 AIPS 작업 폴더의 기존 A0·A1 변경을 보존한다. 자동 커밋·push·다음 단계 구현은 하지 않는다.
- C++20, 단일 처리 스레드, 시스템 의존성만 사용한다.
- 기본 max_entries=10000, idle_timeout=120초. 양수 설정만 허용한다.
- IP 전체 길이 기준 바이트 수, 최초 관측 방향, 마이크로초 캡처 시각을 사용한다.
- A3 재조립·룰·JSONL·live/Inline·AI·IPC는 구현하지 않는다.
- 실행 로그·원본 PCAP·빌드 결과는 Git 제외 디렉터리에 둔다.

## Review Focus

- 첫 패킷이 정규화한 키의 높은 endpoint에서 왔을 때도 fwd 방향 유지: Task 1 FirstObservedDirectionIsNotKeyOrder.
- 만료 경계·역순·극단 시각에 의한 잘못된 ID 재사용/정수 오류: Task 1 ExpiryBoundary, BackwardClock, ExtremeTimestamps.
- 용량 초과가 기존 Flow를 축출하거나 무제한 상태를 만들지 않음: Task 1 CapacityPreservesExisting, BoundedManyFlows.
- CLI 숫자 설정의 0·부호·중복·범위 초과가 파일 처리 전에 거부됨: Task 2 RejectsInvalidSettings.
- 손상 패킷이 상태를 생성하지 않으면서 캡처 시계는 진행하고, 추적 실패가 성공으로 숨겨지지 않음: Task 2 MalformedPacketAdvancesExpiry, CapacityIsVisible.

## Task 1: Flow 자료형과 테이블

**Files:** 새 `include/miniips/flow.hpp`, `include/miniips/flow_table.hpp`, `src/flow_table.cpp`, `tests/test_flow_table.cpp`; `CMakeLists.txt`, `tests/CMakeLists.txt` 연결.

**Interfaces:**

- 입력: 기존 `ParsedPacket`.
- `FlowEndpoint{ip, port}`, 정렬 endpoint와 protocol을 갖는 `FlowKey`, `FlowKeyHash`, `make_flow_key(packet)`.
- `FlowDirection::Forward/Backward`, `TcpFlowState::Observed/SynSeen/Established/Closing/Closed/Reset`.
- `FlowDirectionStats{packets, bytes, iat_sum_us, iat_samples, last_seen, syn_count, ack_count, fin_count, rst_count, psh_count}`.
- `FlowSnapshot{flow_id, key, first_source, first_seen, last_seen, fwd, bwd, tcp_state}`.
- `FlowObservation{flow, direction, created}`, `FlowError::CapacityExceeded`, `FlowResult=variant<FlowObservation,FlowError>`.
- `FlowTableConfig{max_entries, idle_timeout}`, `FlowTableStats{created, expired, rejected, active}`.
- `FlowTable(config={})`, `observe(packet)->FlowResult`, `expire(microseconds)->size_t`, `find(key)->optional<FlowSnapshot>`, `stats()->FlowTableStats`, `size()->size_t`.

- [x] Write tests for capture/IAT/flag counters, partial handshake, full observed handshake, FIN/RST terminal states and UDP state absence.
- [x] Write tests for before/exactly at the 120-second boundary, bidirectional activity renewal, late timestamps, capacity rejection/reuse, snapshot copies, invalid metadata/config and int64 timestamp extremes.
- [x] RED: configure the new test target and build it before Flow headers exist. Expected: failure identifying the missing Flow interface; save log. These are tests against the real module, not mocks.
- [x] Implement the public value types and bounded map. Use checked uint64 counter addition; update per-entry state on a copy before committing. Expire at elapsed >= timeout, reject only new keys when full, never retain payload.
- [x] GREEN: run `miniips_flow_tests` and full CTest. Expected: all new tests and the 67 existing tests pass.

## Task 2: PCAP CLI와 실제 프로세스 연결

**Files:** 새 `tests/test_cli_flow.cpp`, `tests/fixtures/flow_fixtures.hpp`, `tests/check_flow_cli.cmake`; 수정 `src/cli.cpp`, `tests/fixture_writer.cpp`, 두 CMake 파일.

**Interfaces:**

- Task 1의 FlowResult, stats, FlowTableConfig를 사용한다.
- PCAP 모드에 `--max-flows N`, `--flow-idle-timeout-seconds N`을 추가한다. 기본값 및 기존 0/1/2 종료 코드 계약 유지.
- 정상 packet 줄에 `flow_id`, `direction`, fwd/bwd packets·bytes 추가. 용량 거부는 `flow_id=untracked direction=unknown`과 `flow_error ... reason=capacity_exceeded`.
- EOF에 `flow_summary created=N active=N expired=N rejected=N`을 출력한다. 기존 pcap_summary의 의미는 유지한다.
- 독립된 고정 PCAP: flow_bidirectional(1·2·3초, 정방향/역방향/정방향), flow_expired(1·2·122초), flow_capacity(TCP·UDP·역 TCP).

- [x] Write CLI tests: same ID/reverse counters, new ID after expiry, visible capacity rejection with continued tracking of the old key, custom timeout, option ordering, invalid/huge settings, malformed packet handling and expiry advancement.
- [x] RED: build and run the new CLI tests against the existing A1 CLI. Expected: missing Flow output and rejected new options, while file reading itself works. Save actual assertion failures.
- [x] Implement CLI integration and strict from_chars parsing; seconds must fit int64 microseconds before multiplication. Expire on malformed packets using their validated capture timestamp without creating a Flow.
- [x] Add generated fixtures and three real-process CTest checks. Expected bidirectional final fwd/bwd=2/1, bytes=90/45; expired created=2 expired=1; capacity max=1 created=1 rejected=1.
- [x] GREEN: run new CLI tests and full CTest, format check. Expected: no regression, expected malformed-file error handling retained.
