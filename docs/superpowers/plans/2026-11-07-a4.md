# A4 JSON Rule Engine Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** 검증된 JSON 룰로 packet/stream alert/pass/drop을 결정하고 재전송 판정과 중복 이벤트를 분리한다.
**Architecture:** 불변 RuleSet과 사전 KMP 실패 함수, 관련 prefix 구간, 방향/SID별 발행 watermark를 사용한다. PCAP CLI에 선택 --rules를 연결한다.
**Tech Stack:** C++20, nlohmann/json, GoogleTest, Linux CMake/Ninja.
**Spec:** [승인 설계](../specs/2026-11-07-a4-design.md).

## Global Constraints

- JSON1 MiB, 1024룰, ASCII content1~4096, message1~1024 UTF-8 bytes, depth8; strict types/duplicate keys/SID/unknown fields.
- sid uint32 positive, priority int32, ports0~65535; stream+tcp only. priority/sid ascending; alert continues, pass/drop terminates.
- KMP, direction/SID dedup arrays32 MiB default; max_flows matches FlowTable; no silent Allow on resource failure.
- Native current-folder execution; preserve changes, no commit/push. A3 baseline HEAD6200425, tests146.
- A4 only. IPS A0~A8 → user self-test → user direction → B0/AI. No A5/real DROP/AI work.

## Review Focus

- Duplicate JSON keys/deep nesting rejected before full DOM; disabled rules validated (Task1).
- Packet/stream, port direction, priority and suppressed terminal decisions remain distinct (Task2).
- Half/wrap/FIN/overlap/current accepted prefix ranges exclude rejected bytes (Task2).
- ACK/unrelated suffix does not replay stream verdict, retransmission still drops (Task2).
- Bad rules abort before PCAP output; memory/expiry/output failures explicit (Task3).
